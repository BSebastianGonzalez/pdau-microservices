# Complaint Register

**Source:** [pdau_complaint_register](https://github.com/BSebastianGonzalez/pdau_complaint_register)

The complaint register is the intake service for anonymous reports. It stores the initial complaint information and supporting evidence, exposes the catalog data needed by the registration flow, and emits events that allow reporting and management services to react without sharing its database.

- **Technology:** Java 21, Spring Boot, JPA, MySQL, Cloudinary, RabbitMQ, Eureka Client.
- **Default port:** `8080`.
- **Application name:** `complaint`.
- **Responsibilities:** create and consult complaints, retrieve complaints by tracking token, manage categories and states, and attach evidence.
- **Representative routes:** `/api/denuncias`, `/api/evidencia`, `/api/categorias`, and `/api/estados`.

The service publishes or consumes RabbitMQ events and uses environment variables for database, broker, and Eureka connectivity.

## Internal structure

- `DenunciaController` and `DenunciaService` handle complaint creation, consultation, token lookup, and archived/non-archived queries.
- `ArchivoDenunciaController` and `ArchivoDenunciaService` manage evidence associated with a complaint.
- `CategoriaController`/`CategoriaService` and `EstadoController`/`EstadoService` manage catalog entities.
- `Denuncia`, `ArchivoDenuncia`, `Categoria`, and `Estado` are the main JPA entities.
- DTOs separate HTTP payloads from persistence models.
- `RabbitConfig` declares broker infrastructure.
- `DenunciaCreadaEvent`, `DenunciaEstadoActualizadoEvent`, `DenunciaArchivadaEvent`, `DenunciaDesarchivadaEvent`, and `RespuestaRegistradaEvent` represent cross-service events.
- Listeners receive events generated by management and keep this service synchronized where the workflow requires it.

## Main flow

1. The anonymous user submits a complaint through `/api/denuncias`.
2. `DenunciaService` validates the request, assigns its initial state and generates the tracking token.
3. The complaint and related evidence are persisted in the register database; file content is handled through the configured storage integration.
4. A complaint-created event is published through RabbitMQ for reporting and other consumers.
5. The user later consults the case using `/api/denuncias/token/{token}` without authenticating.
6. State, response, archive, and unarchive events allow the register and reporting views to remain aligned with the management lifecycle.

## Installation

```bash
git clone https://github.com/BSebastianGonzalez/pdau_complaint_register.git
cd pdau_complaint_register
./mvnw spring-boot:run
```

On Windows use `mvnw.cmd spring-boot:run`. Configure `DB_URL`, `DB_USER`, `DB_PASSWORD`, `RABBITMQ_URL`, and `SERVICE_DISCOVERY`. The application name is `complaint` and the default port is `8080`.
